`go-meshtastic-serial2tcp` — TCP-мост для Meshtastic-радиостанций, подключённых через последовательный порт. Написан на Go.

Приложение подключается к Meshtastic-устройству по USB или другому последовательному интерфейсу и предоставляет к нему доступ по TCP, чтобы десктопные приложения, скрипты, контейнеры и удалённые инструменты могли работать с радио без прямого доступа к порту.

В отличие от простого форвардера, этот мост рассчитан на **одновременную работу нескольких клиентов**: он поддерживает одну общую сессию с радио, мультиплексирует кадры для нескольких TCP-клиентов, кэширует ответы конфигурации и предотвращает конфликты при переподключениях.

## Основные возможности

- **TCP-мост для Meshtastic** — доступ к радио через последовательный порт по сети
- **Многоклиентский доступ** — несколько клиентов через одну общую сессию
- **Кэширование конфигурации** — снижение конфликтов между клиентами при повторных запросах
- **Обнаружение через mDNS** — автоматическое обнаружение сервиса в локальной сети
- **Готовность к Docker** — развёртывание на серверах, Raspberry Pi и в контейнерах
- Написан на **Go** с использованием сгенерированных protobuf-типов Meshtastic

## Сценарии использования

- **Подключение нескольких десктопных клиентов к одному радио** без конкуренции за последовательный порт.
- **Проброс USB-подключённого Meshtastic-узла в Docker-контейнеры** или другие изолированные сервисы без прямого доступа к порту.
- **Общий доступ к одному радио в локальной сети** для локальных приложений, удалённых скриптов и контейнеров.
- **Устранение конфликтов за порт**, когда нескольким клиентам одновременно нужны чтение, конфигурация или видимость пакетов.

## Почему не простой форвардер?

Простой форвардер умеет прокидывать байты по TCP, но не понимает логику сессий Meshtastic. Как только клиентов становится больше одного, начинаются проблемы.

Этот мост разработан специально для Meshtastic и добавляет то, чего нет у простого форвардера:

- **Работа с несколькими клиентами** через одну общую сессию с радио
- **Кэширование конфигурации** — повторные запросы `want_config_id` не сбрасывают состояние
- **Устойчивость к переподключениям** — корректная обработка `rebooted` от радио и отключений клиентов
- **Управление сессией на стороне моста** — один клиент не может сломать состояние для остальных

Коротко: простой форвардер пересылает байты, а этот сервис поддерживает стабильную сессию Meshtastic для нескольких клиентов.

## Частые вопросы

### Почему не `ser2net`?

`ser2net` — хороший универсальный инструмент для проброса последовательного порта по сети, но он работает с соединением как с потоком байтов. Клиенты Meshtastic ожидают стабильного поведения сессии, обмена конфигурацией и предсказуемой обработки переподключений. `go-meshtastic-serial2tcp` понимает эти сценарии и не даёт клиентам мешать друг другу.

### Почему не `socat`?

`socat` отлично подходит для быстрого проброса и тестирования. Но он бесполезен, когда нескольким клиентам Meshtastic нужно длительно делить одно радио: в нём нет управления сессией, кэширования конфигурации и обработки переподключений, специфичной для Meshtastic.

### Почему не прямой проброс USB?

Прямой проброс USB подходит, когда радио использует один процесс на одной машине. Но он неудобен, если нужно:

- делить радио между несколькими приложениями,
- отдавать радио контейнерам,
- подключаться с другой машины в сети,
- избегать конфликтов за владение устройством.

Для таких случаев и создан этот проект.

## Требования

### Для запуска
- Доступ к последовательному устройству, например `/dev/ttyUSB0` (Linux) или `/dev/tty.usb*` (macOS)

### Для сборки из исходников
- Go 1.26+
- Git (для клонирования с submodules)

### Для разработки (перегенерация protobuf-файлов)
- `protoc` — компилятор Protocol Buffers
- `protoc-gen-go` v1.36.11+ — генератор Go-кода для protobuf
- `make` — для использования команд из Makefile

## Установка и запуск

Установка через `go install`:

```bash
go install github.com/skrashevich/go-meshtastic-serial2tcp@latest
```

Запуск с флагами:

```bash
meshtastic-serial2tcp \
  --device /dev/ttyUSB0 \
  --baud 115200 \
  --tcp-port 4403
```

Запуск с переменными окружения:

```bash
SERIAL_DEVICE=/dev/ttyUSB0 \
BAUD_RATE=115200 \
TCP_PORT=4403 \
meshtastic-serial2tcp
```

При ошибке доступа к устройству проверьте права пользователя — например, добавьте его в группу `dialout` на Linux или запустите с повышенными правами.

## Docker

Запуск готового образа из GitHub Container Registry:

```bash
docker run --rm \
  --device /dev/ttyUSB0 \
  -p 4403:4403 \
  -e SERIAL_DEVICE=/dev/ttyUSB0 \
  -e BAUD_RATE=115200 \
  -e TCP_PORT=4403 \
  ghcr.io/skrashevich/go-meshtastic-serial2tcp:latest
```

Пример с docker-compose:

```yaml
services:
  meshtastic-serial2tcp:
    image: ghcr.io/skrashevich/go-meshtastic-serial2tcp:latest
    container_name: meshtastic-serial2tcp
    restart: unless-stopped
    environment:
      SERIAL_DEVICE: /dev/ttyUSB0
      BAUD_RATE: "115200"
      TCP_PORT: "4403"
    ports:
      - "4403:4403/tcp"
    privileged: true
    devices:
      - /dev/ttyUSB0:/dev/ttyUSB0
```

Примечания:

- Для работы mDNS на Linux может потребоваться `--network host`, чтобы multicast-анонсы доходили до локальной сети. Если mDNS не нужен, укажите `-e MDNS_ENABLED=false`.
- Если контейнер не может открыть устройство, убедитесь, что оно проброшено и права доступа корректны.

## Конфигурация

Переменные окружения и соответствующие флаги:

| Переменная | По умолчанию | Флаг | Описание |
|---|---|---|---|
| `SERIAL_DEVICE` | `/dev/ttyUSB0` | `--device` | Путь к последовательному устройству |
| `BAUD_RATE` | `115200` | `--baud` | Скорость порта |
| `TCP_PORT` | `4403` | `--tcp-port` | TCP-порт сервера |
| `RECONNECT_DELAY` | `5` (сек.) | `--reconnect-delay` | Задержка переподключения |
| `MDNS_ENABLED` | `true` | `--mdns` | Включить mDNS-анонсирование |
| `READ_ONLY_CLIENTS` | `false` | `--read-only-clients` | Режим «только чтение» для неосновных клиентов |
| `SERVICE_NAME` | `Meshtastic Serial Bridge (<device>)` | `--service-name` | Имя mDNS-сервиса |
| `DEBUG` | `false` | `--debug` | Отладочный вывод |

Проверка здоровья:

- `--healthcheck` — завершается с кодом 0, если TCP-порт доступен на `127.0.0.1`.

Отладочный вывод:

- Включается через `DEBUG=true` или `--debug`. Показывает подробности протокола в логах. Полезен для диагностики, но может быть многословным.

## Обнаружение через mDNS

Когда включено, сервис публикует запись `_meshtastic._tcp.local.` с информацией об устройстве и скорости порта. Если mDNS не нужен или не работает в вашей среде, отключите через `MDNS_ENABLED=false` или `--mdns=false`.

## Работа с несколькими клиентами

Брокер поддерживает одну общую сессию с радио и мультиплексирует её для всех TCP-клиентов. Основные принципы:

- **Основной клиент.** Первый подключившийся клиент становится основным (используется для упорядочивания). При его отключении роль автоматически переходит к одному из оставшихся.
- **Кэширование `want_config_id`.** Если кэш заполнен, запрос `want_config_id` обслуживается из кэша — как для основного, так и для остальных клиентов. Только при холодном старте (пустой кэш) или после сброса по `rebooted` запрос передаётся радио с собственным nonce брокера. Это предотвращает цикл, в котором каждый `want_config_id` вызывал у прошивки ответ `rebooted=true`, и клиент отключался до заполнения кэша.
- **Поглощение `FromRadio.rebooted=true`.** Брокер очищает кэш и повторно отправляет незавершённые запросы конфигурации с новыми nonce. Сам кадр `rebooted` клиентам не пересылается, так как некоторые клиентские библиотеки воспринимают его как сигнал разрыва соединения.
- **Блокировка `ToRadio.disconnect`.** Сессия с радио живёт дольше отдельных TCP-клиентов. Пересылка `disconnect` от клиента раньше заставляла прошивку сбрасывать состояние и отвечать `rebooted=true` на следующий `want_config_id`.
- **Зеркалирование исходящих пакетов.** Когда клиент отправляет пакет (при `READ_ONLY_CLIENTS=false` или если он основной), пакет уходит в радио и одновременно рассылается остальным клиентам как `FromRadio`, чтобы их интерфейсы оставались синхронизированными.
- **Отключение медленных клиентов.** Рассылка `FromRadio` использует ограниченный буфер на клиента. Если клиент не успевает забирать данные, он отключается — вместо молчаливой потери кадров.
- **Восстановление после ошибок кадров.** Некорректные длины кадров на последовательной линии (`ErrInvalidFrame`) логируются, после чего reader синхронизируется на следующей паре магических байтов, не роняя весь брокер.

## Разработка

### Сборка из исходников

Клонирование репозитория с submodules:

```bash
git clone --recurse-submodules https://github.com/skrashevich/go-meshtastic-serial2tcp.git
cd go-meshtastic-serial2tcp
```

Если уже клонировали без submodules:

```bash
git submodule update --init --recursive
```

Сборка:

```bash
go build -o go-meshtastic-serial2tcp .
```

Или через Makefile:

```bash
make build
```

### Генерация protobuf-файлов

Проект использует определения Protocol Buffers из официального репозитория [Meshtastic protobufs](https://github.com/meshtastic/protobufs), подключённого как git submodule в [protobufs/](protobufs/).

#### Требования

- `protoc` — компилятор Protocol Buffers ([инструкция по установке](https://grpc.io/docs/protoc-installation/))
- `protoc-gen-go` v1.36.11+:
  ```bash
  go install google.golang.org/protobuf/cmd/protoc-gen-go@v1.36.11
  ```

#### Перегенерация

Через Makefile (рекомендуется):

```bash
# Проверить наличие инструментов и версии
make tools-check

# Перегенерировать все protobuf-файлы
make proto

# Обновить submodule protobufs до последней версии
make proto-update

# Удалить сгенерированные файлы
make proto-clean

# Показать все доступные команды
make help
```

Вручную:

```bash
# Создать временную директорию
mkdir -p github.com/meshtastic/go/generated

# Сгенерировать файлы
protoc \
  --proto_path=protobufs \
  --go_out=. \
  protobufs/meshtastic/*.proto protobufs/nanopb.proto

# Переместить в нужное место
mkdir -p internal/meshtastic
mv github.com/meshtastic/go/generated/*.pb.go internal/meshtastic/
rm -rf github.com
```

Сгенерированные файлы используют `package generated` и находятся в [internal/meshtastic/](internal/meshtastic/).
